# Separate desktop and Wasm builds

The root `build.zig` selects **one** platform graph. Normal application builds do
not run a Python application builder, invoke another `zig build`, or configure
the other platform. The graph-isolation test queries each configuration's help
menu, without building the other application.

| Command | Output / action |
| --- | --- |
| `zig build` | Desktop application: `zig-out/desktop/bin/haystack_game`, shared raylib in `zig-out/desktop/lib` |
| `zig build -Dplatform=wasm` | Complete browser bundle: `zig-out/wasm/index.html`, Rust wallet, JS bindings, Zig renderer and assets |
| `zig build run` | Build/run the desktop application |
| `zig build run -Dplatform=wasm` | Build/serve the browser application at `http://127.0.0.1:8000` |
| `zig build test` | Desktop application tests |
| `zig build test-wallet` | Native Rust suite, C-header check, Zig wallet/Spilman ABI tests |
| `zig build test -Dplatform=wasm` | Full browser build, database conformance tests, ephemeral fake mint, Chromium tests, fixture cleanup |
| `zig build test-wallet -Dplatform=wasm` | Browser database conformance tests on the host |
| `zig build test-mint -Dplatform=wasm` | Build/serve the browser app with a localhost-only fake mint at port 18787 |
| `zig build setup -Dplatform=wasm` | Provision browser tools without building the application |
| `zig build test-build` | Test graph isolation and cached/offline tool-provisioning contracts |

`zig build -Dtarget=wasm32-emscripten` also selects the **complete** Wasm graph.
It no longer means renderer-only. For deliberate renderer-only development use
`zig build renderer -Dplatform=wasm`. The old `zig build browser` command now needs
`-Dplatform=wasm`; prefer the unambiguous commands above. The misleading native
`wallet-wasm-check` step has been removed; the browser has its own Rust package.

## What stays separate

| | Desktop | Wasm |
| --- | --- | --- |
| Build implementation | `build/desktop.zig` | `build/wasm.zig` |
| Rust package | `vendor/cdk-wallet-ffi` | `browser/wallet` |
| Rust target | Explicit native Linux host triple | `wasm32-unknown-unknown` |
| Rust build cache | `vendor/cdk-wallet-ffi/target` | `browser/wallet/target` |
| Zig/raylib target | Native Linux, dynamic raylib | `wasm32-emscripten`, static archives linked by emcc |
| Wallet boundary | Translated C header and static archive | Async JS bindings generated by wasm-bindgen |
| Native libraries | unwind, pthread, dl, rt, util, m | Never linked |
| Runtime/storage | Tokio runtime, SQLite, Unix files | LocalSet/browser async executor, localStorage/Web Locks |
| Tools provisioned | Pinned Rust host compiler/target only | Pinned Rust + Wasm target, local wasm-bindgen, Emscripten |

The shared wallet-policy and cryptographic **source** is deliberately reused;
compiled artifacts and platform dependencies are not. A normal browser build
does not compile the native wallet crate, native tests, or desktop executable.
A normal desktop build does not provision Emscripten/wasm-bindgen or compile the
browser wallet. Browser **tests** explicitly need a native fake-mint executable;
that helper has its own `browser/wallet/target/test-mint` cache and is never linked
into or shipped with the browser bundle.

Desktop support is currently native Linux (x86_64/aarch64). A foreign desktop
target is rejected rather than silently linking a host Rust archive into it.
The browser target is explicitly wasm32-emscripten; conflicting platform/target
options fail during configuration.

## Tool setup is owned by Zig

Install the host prerequisites once: **Zig 0.17.0**, **Python 3**, and **Rustup**
with its Cargo shim on `PATH`, plus a working native C linker and Clang/LLVM for
Rust dependencies that compile C code. Desktop additionally needs the normal
raylib/Linux development libraries and libunwind. Browser tests require **Node 22+** and
**Chromium** (`CHROMIUM=/path/to/browser` is supported). The build never uses sudo
or attempts to install OS packages or the browser.

Application tool provisioning happens automatically, only in the selected graph:

1. Check for Rust **1.99.0**, installing the minimal toolchain only if missing.
   No global default Rust toolchain is changed.
2. For Wasm, install `wasm32-unknown-unknown` only when missing.
3. For Wasm, install wasm-bindgen CLI **0.2.130** with a locked Cargo installation
   under `.zig-cache/tools/wasm-bindgen-0.2.130`, not `~/.cargo/bin`.
4. For Wasm, provision/check Emscripten **4.0.19**. Already-installed tools are
   checked without network updates.

The small scripts in `build-support/` only handle idempotent tool provisioning
and test-server lifecycle. Zig owns the Rust build, generated bindings, renderer
compilation/linking, dependency ordering, caching and installation directly.
Cargo still owns its dependency/incremental cache and is invoked each build so
edits to the shared Rust sources cannot leave Zig linking a stale archive.
The wasm-bindgen output is a generated Zig build artifact and is cached when the
Rust `.wasm` and tool are unchanged. Static assets have their own install steps.

## Options and offline builds

```sh
zig build -Dplatform=wasm -Doptimize=ReleaseSafe
zig build -Dplatform=wasm --prefix /path/to/output
zig build -Dplatform=wasm -Doffline
zig build -Doffline
```

Outputs remain separated under `<prefix>/desktop` and `<prefix>/wasm`.
Changing the install prefix does not force a second renderer build or copy a
whole nested build directory into the result. Old `zig-out/bin`, `zig-out/browser`
and `zig-out/web` products from the previous build layout are not deleted.

Default optimization is **Debug for desktop**, **ReleaseSmall for Wasm**.
An unqualified `--release` selects ReleaseSafe on desktop and ReleaseSmall on Wasm.
`-Doptimize=Debug` uses Cargo's debug profile; the release modes use Cargo release
with matching opt-level (`2`, `3`, `s` for safe/fast/small). ReleaseSafe enables
Rust overflow checks. The native panic strategy remains unwind; browser panic
limitations remain documented in [browser-wallet.md](browser-wallet.md).

`-Doffline` forbids provisioning downloads and adds `--offline --locked` to Cargo.
Missing tools fail with an explanation instead of fetching silently. Run once
online (or `setup`) first. Zig dependencies must already be cached too; use
Zig's own dependency-fetch controls when prepopulating a fully offline machine.

Optional advanced overrides:

- `-Drust-toolchain=...` changes the explicitly selected Rustup toolchain.
- `-Dwasm-bindgen=/path/to/wasm-bindgen` bypasses the local install **only** after
  validating version 0.2.130; this option is not part of the desktop graph.
- `-Dport=9000` changes the plain browser development-server port.
- `BROWSER_TEST_PORT=0 zig build test-mint -Dplatform=wasm` allocates an available
  fake-mint port. Automated browser tests always choose their own ephemeral port.

Normal `run -Dplatform=wasm` only serves static assets; it never starts a fake
mint or creates funds. Fake mint behavior is explicit and test-only.

## Refactor verification

Verified on this Linux machine:

- Normal Wasm build automatically installed its managed wasm-bindgen and Rust
  Wasm target without a CLI-path override or manual Cargo setup.
- Desktop and Wasm cached builds passed with `-Doffline` and separate fresh
  `--prefix` directories. Each prefix contained only its selected platform.
- Wasm bindings and renderer steps reported cache hits when changing the prefix.
- `zig build test-build`: **14** provisioning/graph-isolation tests passed.
- `zig build test-wallet`: **51** Rust tests, **26** Zig tests and header check passed.
- `zig build test -Dplatform=wasm`: **51** database tests and **42** Chromium checks
  passed; the helper mint's ephemeral port was closed after the test step.
- The full browser suite also passed with `-Doptimize=Debug -Doffline` and a fresh
  custom output prefix, verifying that Debug is not silently replaced by release.
- Conflicting native/Wasm target selections failed during configuration, before
  any application compilation.
